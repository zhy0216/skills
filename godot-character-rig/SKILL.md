# Godot 角色拆图与骨骼

把用户的角色图转成可编辑、可复用的 Godot 2D 角色。默认沿用原画设计与项目引擎版本，以原生 `Skeleton2D + Bone2D + AnimationPlayer` 交付。拆图素材和定位清单是中间产物；用户只要求拆图时，交付到该阶段即可。

## 与现有技能协作

- **图像阶段**：使用当前环境的 `imagegen` 技能和内置图像工具。先查看原图；局部图、原画、标注图分别说明角色。实际工具参数以当前工具定义为准。普通编辑不要求 API key；API/CLI 路径只在用户已选择时使用。
- **Godot 阶段**：读取已安装的 `godot-2d-animation/SKILL.md`，按任务加载其 cutout / skeleton 或 IK 参考。常见位置是本技能的同级目录、`~/.agents/skills` 和 `$CODEX_HOME/skills`。不要加载整套 Godot 技能。
- 依赖缺失时，按本技能的原生绑定参考继续；需要安装时只安装对应技能。上游地址见 [Godot 实现参考](references/godot.md)。示例代码需要通过本地引擎验证，方法和类型以对应版本官方文档为准。
- 本技能补充拆图与素材交接流程，不要求 Spine、Gemini 或第三方在线服务。

## 开始前

先利用对话和项目文件确定原图、目标项目、Godot 版本及所需动作。缺原图时请用户提供图片或本地路径；这不妨碍先检查项目。只问真正阻塞的事项，不重复确认已明确的画风、输出位置或工具选择。

常规默认：保留原图视角、轮廓、服饰、配色与左右不对称；左右按角色自身区分。未知动作需求时先做 rest pose 和小幅关节试动，不自行增加整套战斗动画。没有项目且用户要求可运行结果时，在选定输出目录创建独立的最小 Godot 示例工程。

## 按素材选择拆图方式

| 输入情况 | 优先做法 |
| --- | --- |
| 已有 PSD 图层或部件 PNG | 复用已有像素，检查缺失部件、命名、比例和坐标，不重新生成整套素材 |
| 单张完整角色图 | 默认先制定分件清单，逐部件提取、补全；脸和标志性纹理优先保留 |
| 像素画、要求像素完全一致 | 优先源图层/精确蒙版；图像模型可辅助补画，但不能保证逐像素一致 |
| 只需尾巴、衣物等小幅弯曲 | 可局部采用 `Polygon2D` 网格变形，避免不必要的全身拆分 |
| 用户明确优先快速概念验证 | 可先生成整张部件摊开图；仍要逐件确认、定位并回拼验收 |

真正处理图片前，读取 [拆图策略与提示词](references/splitting.md)。精确裁切、像素回贴等方案需要当前环境允许的图像处理工具；不要把它们写成内置生图工具已有的保证，也不要未经用户选择转向 Python 图像编辑或付费 API。

## 工作流

1. **拆分设计**：根据动作决定哪些部位要独立运动。列出部件、所属骨骼、关节点、遮挡前后关系、需要补画的区域。保留可见原画；完全不可见的部分标为推测补全。原图缺乏足够信息时，不承诺还原其真实隐藏结构。
2. **建立小样**：新角色或不确定画风优先用躯干与一条肢体验证拆分、回拼、关节旋转。已有通过验证的分层素材可直接使用。小样通过后继续完成用户请求，不把人工批准作为固定关卡。
3. **逐件产图**：每次携带原画作为稳定参考；交付有真实 alpha 的部件 PNG。保留关节搭接量，补画遮挡区，记录提取与生成的来源。一个部件失败只修该部件，避免反复重画全身。
4. **校准和回拼**：统一使用原图像素坐标，记录最终 PNG 左上角的位置和 `texture_scale`；不同分辨率的部件可在 Godot 内等比缩放对齐，不必重采样 PNG。按层级拼回，检查身份、轮廓、大小、缝隙和边缘。坐标与生成布局都是待核验的估计，不把 GPT 猜测的关节点当作精确标注。
5. **写定位清单**：按 [素材与坐标契约](references/manifest.md) 保存 `rig.json`。骨骼位置和部件位置分开记录，裁图留白改变后同步更新清单。
6. **原生绑定**：读取 [Godot 实现与验证](references/godot.md)，搭建骨骼与部件。刚性切件可用随附脚本生成初始场景；需要柔性变形时再建立 `Polygon2D` 权重。
7. **制作并验收动作**：先检查 RESET/rest、关节极限和绘制顺序，再完成用户指定的动画。循环动作检查首尾一致和脚底滑动。只有状态混合需求才增加 `AnimationTree`。

## 随附脚本

`scripts/build_cutout.py` 使用 Python 标准库读取清单和 PNG 尺寸，输出 Godot 4 刚性切件 `.tscn`，包含骨骼、贴图和 RESET 动画。它不编辑图片、不推断关节点、不生成动作或网格权重。

```bash
python3 /path/to/godot-character-rig/scripts/build_cutout.py \
  --project /path/to/game --manifest /path/to/game/art/hero/rig.json --check

python3 /path/to/godot-character-rig/scripts/build_cutout.py \
  --project /path/to/game --manifest /path/to/game/art/hero/rig.json \
  --output res://characters/hero/hero-rig.tscn
```

脚本拒绝覆盖已有文件。场景开始人工调整或添加动画后，将其作为正式源文件维护；需要重新生成时输出到新路径，再有选择地合并差异。

## 交付与完成条件

完整角色任务应包含：部件 PNG、`rig.json`、原生 `.tscn`、所需动画，以及原位回拼/关节试动预览。预览与检查结果放在项目现有产物目录；用户只要素材时不额外搭工程。

- rest pose 能拼回原画，偏移与比例没有因裁图或 PNG 留白变化而错位。
- 肩、肘、髋、膝等所需关节在目标动作范围内无明显露缝、断肢、错误遮挡。
- 场景打开和资源导入无新增错误，骨骼 rest 已保存；动画播放与回到 RESET 都正确。
- 检查头发/白衣/半透明边缘是否被误删，背景确实透明；不以棋盘格图案冒充 alpha。
- 最终说明输出路径、已验证的引擎版本、实际完成的动作，以及仍需调整的部件。headless 通过只代表结构可加载，不能当作视觉验收。

如果连续两次针对同一部件修正仍未改善，保留最好的结果，说明具体问题并调整拆分或表示方式；不无限重试生图。只有缺少必要素材或工具选择阻塞下一步时再请求用户补充。
